Settings guide
← Back to status

What each setting on this node does, and which ones you can change from the Settings menu (the ☰ button on the status page). Most changes take effect at the next capture cycle — the node re-reads its config every loop.

Transport mode

How detections leave the node. Switchable from Settings → Transport mode.

Relay mode = relay
For off-grid sites. Forwards JPGs (and MP3s) over the XBee radio to the SPARROW hub, which has the backhaul. This is the default. Shown as XBee in the menu.
Direct mode = direct
For connected sites. Skips the radio and uploads over Wi-Fi / 4G straight to the SPARROW cloud. Needs an upload server and an onboarding key (see Cloud upload below). Shown as 4G in the menu.

XBee radio (relay mode)

The long-range DigiMesh link to the hub. Re-apply the standard radio config from Settings → Configure XBee.

Hub NI xbee.master_ni
The name the node looks for when finding the hub over the air. Default SPARROW_MASTER. This is set on the hub's radio and rarely changes.
Pinned hub address xbee.dest64
The hub's 64-bit address the node sends to. Filled in automatically the first time the node discovers the hub. If the hub's XBee chip is replaced, this becomes stale — use Settings → Rediscover hub to find the new one. Leave it blank to auto-discover every run.
Radio family xbee.family
868 (XBee SX) or 900 (XBee-PRO 900HP). Both ends of a link must match. The 900 family skips the BR command during configuration (its RF rate is fixed in firmware).
Window & chunk xbee.window / xbee.chunk
How many chunks are in flight at once and how many bytes per chunk. Bigger = faster on a clean link, but the first chunk plus the file's name/size header must stay under the radio's max payload (NP, 256 bytes on 900HP) — keep chunk around 180–220.
Port & baud xbee.port / xbee.baud
The serial device (default /dev/ttyUSB0) and speed (115200). If the FTDI adapter re-numbers on reboot the node falls back to a /dev/serial/by-id path automatically — prefer a by-id path here to avoid surprises.

Configure XBee re-applies API mode, network ID 1234 and the routing/rate settings. Rediscover hub only re-resolves the hub's address — use that after a hub chip swap.

Image capture & compression

Applied to every JPG before it's detected and sent.

Compression image.enable_compression
Re-encode JPGs to shrink them before transmit. Strongly recommended on the radio.
JPEG quality image.jpeg_quality
1–100. Lower = smaller files, less detail. 82 is a good balance.
Max dimension image.max_dim
Longest edge in pixels; larger images are scaled down. 800 keeps files to tens of KB — a few hundred radio chunks. Set 0 to leave images full size.

Audio recording

When the mic (e.g. a USB AudioMoth) records. Switchable from Settings → Audio recording. Independent of the PIR/motion — that only triggers images.

Schedule mode audio.MODE = "schedule"
Time-based (the default). Records SCHEDULE.duration_seconds of audio once every SCHEDULE.interval_minutes — e.g. 10 s every 30 min.
Threshold mode audio.MODE = "threshold"
Sound-activated (VOX). Monitors a 1 s sample; when its peak amplitude exceeds THRESHOLD it records a RECORD_DURATION-second clip. THRESHOLD is an int16 peak (1–32767) — lower = more sensitive.

Clip length (both modes) is capped at 10 s — audio ships over XBee as MP3, and longer clips are minutes of radio airtime. Recorded as WAV (48 kHz mono), then after the audio detector runs, bird-hit clips are encoded to MP3 at encode_bitrate_kbps and the WAV is deleted. Set enabled to turn the whole pipeline off.

Detectors

On-device AI that decides what's worth sending. Toggle blank-forwarding from Settings → Blank frames.

Image detector detector.*
MegaDetector (vision). conf_threshold is the minimum confidence to call a detection (0–1). keep_blanks — when on, empty frames are still sent; when off, they're dropped to save airtime.
Audio detector audio_detector.*
MD Audio Birds (acoustics). Runs as a separate step so the two models never sit in RAM together. Bird-hit clips become an MP3 + sidecar; the WAV is deleted. Same conf_threshold / keep_blanks idea as the image detector.

Push receivers (IP cameras)

Let a Wi-Fi/IP camera drop stills straight onto the node — no USB needed. Point the camera at the node's Wi-Fi AP (10.42.0.1).

FTP ftp.*
Built-in FTP server on port 21. Set user / password to match the camera. Uploaded JPGs land in the image folder and flow through detection like any other capture. enabled starts it with the node.
Email / SMTP email.*
Built-in SMTP receiver on port 2525 for cameras that email snapshots. Images are pulled out of the message and dropped into the same folder.

The sender only transmits .jpg (and .mp3). If a camera also uploads .mp4 clips or .txt files they're ignored by the radio but still fill the disk — turn off video upload on the camera.

Cloud upload (direct mode)

Only used when Transport mode is Direct. Set from Settings → Server settings.

Upload server server.base_url
The SPARROW server the node POSTs to (must start with https://).
Onboarding key / API key
Paste the onboarding key and press Onboard device to bind this unit, or paste an API key directly. The secret is stored on disk and never shown back in the status page.

Timing & monitoring

Capture cycle launcher.loop_sleep_sec
Seconds between capture cycles. Default 1800 (30 min). Lower it for faster turnaround (e.g. an IP camera pushing images), at the cost of more power — the radio and CPU wake more often.
Signal poll signal_monitor.interval_sec
How often the node pings the hub for the link-quality reading shown on the status page. During a file transfer the radio is busy, so the page briefly shows "radio busy" — that's normal.
